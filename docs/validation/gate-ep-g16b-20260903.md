## 三、关键工程发现（影响后续迭代的载荷性事实）

1. **DM VARCHAR 按字符、Doris VARCHAR 按字节**：EP_FLOW.REVIEW_COMMENT 256 字符中文 = 266 字节，stream load 以 DATA_QUALITY_ERROR 过滤整批。解法：DDL 一律 ×4 放宽（cap 65533），教训已写进 DDL 脚本头注释。G5 边缘表当年 varchar(1600) 宽松口径正是对此的隐性规避。
2. **S5 边缘隔离与直连采集的冲突及豁免**：DOCKER-USER 链只允许边缘网段访问 DM，SeaTunnel 直连被 DROP（G16b 计划既定路径被安全规则阻断）。解法：SeaTunnel 容器静态 IP 钉扎（compose `172.20.0.53`）+ `edge-isolation-rules.sh` 增加单项白名单（`ST_INGEST_IP`），平台网段其余容器维持 DROP（quality-runner 实测仍被拒）。防横向语义保留，豁免可审计、幂等、开机重放。
3. **主表 ep_mz_cfzb 陈旧是数据质量信号**：其 8/20 快照缺新处方导致三条 FK 失败；重建为 UNIQUE KEY 后与源库精确一致（11,420），顺带清除了旧表 APPEND 重复（曾 11,442 > 源 11,373）。ep_mz_ypcfmx 同样陈旧，无规则依赖暂未刷新——后续批次处理。
4. **容器网络运维坑组合**：容器 IP 切换后 docker 嵌入 DNS 别名丢失（须 compose 重建而非 network connect）、控制面 HTTP 连接池咬旧 IP（须重启容器）、portal nginx 缓存上游 IP（G9 已知，重启 portal）——三者叠加造就了首轮 SUBMIT_FAILED 风暴，处置过程已沉淀。
5. **控制面 runs API 返回按时间倒序**：`items[-1]` 是最旧运行——对账/重试脚本必须取 `items[0]`（本 Gate 踩坑实录）。

## 四、T5b 弱多源首轮读数与裁决

**第二身份流形态**：`EP-REG`（患者域 C 端注册路径）——属性取 `patient` 表（姓名/性别/电话），机构归属经真实处方活动推导（`patient_card` 机构字段实测全空 0/1777，不能作归属依据）；无就诊卡列（证件号与 KH 不同码空间，不并入 card_no_norm）；卡表 RELATIONSHIP 实测全为「本人」，无亲情账号污染。装载器按 sourceSystem 分发查询（`MpiLoaderService`），rebuild 双流装载（`MpiRebuildService`），H2 集成测试覆盖。

**dev 双流 rebuild 读数**（1441+1441 身份，候选对 45→1,493）：AUTO 360 / REVIEW 1,014 / NO_MATCH 115（否决 26，与单源一致）/ 硬冲突 4。跨流同名属性分歧显著（REVIEW 膨胀即其体现）——双采集路径分布差异真实存在。

**漂移报告**（快照→同 seed 语料→`MpiDriftReportTests`）：**DRIFT 18/27**，漂移几乎全部由 **card 字段结构性缺失**主导（m_missing 0.106→0.55、u_missing 0.038→0.57——EP-REG 无卡是设计使然，非分布噪声）；name m 侧稳定（agree 1.0）。

**裁决：记录漂移，不更新 packaged()。** 依据手册 §三框架：(1) 漂移来源是数据形态变化（第二流无卡）而非可泛化的分布信息；(2) 语义铰链（NEG_RATIO 候选配比、孪生锚）仍是单源锚定——手册明确要求先重锚再谈权重；(3) 直接吸收「无卡」进 m/u 会把覆盖缺口当成信号。**T5b 余项**：语料生成器按双流真实候选构成重锚 + 注册流人工锚点补充 + 重锚后再评估是否重标定（继续归备忘 T5）。

**如实声明的局限**：本报告为「同库跨表弱多源」——EP 与 EP-REG 同源于 EP_TEST 库、共享平台内部 PATIENT_ID，跨流同人对存在构造性关联；真实多源系统（不同库/不同业务系统）的分布差异只会更大。语料切分单位已从「行」改为「人键」（双流快照下旧行级洗牌必然炸零交集断言），该补丁已回填仓库生成器，冻结语料文件不受影响。

## 五、与方案的偏差（如实记录）

1. **增量作业独立建（9+9=18 个作业）**：计划未明确增量形态；沿用 CFZB 先例（全量作业 + 增量窗口作业分离），增量查询含 `TO_TIMESTAMP` 占位符规整。
2. **ep_mz_cfzb 重建超出 9 表清单**：FK 目标陈旧逼迫刷新；借机现代化为 UNIQUE KEY（与 G16b 纪律一致）。ep_mz_ypcfmx 未刷新（无依赖，留待后续批次）。
3. **ep_yb_rx 首次重载跨弃表窗口**：一次运行横跨 DROP/CREATE，只落入尾部批次（1,424/12,688）；表结构稳定后重跑精确对账。属执行时序事故，非机制缺陷（重跑即愈恰证幂等设计）。
4. **OM TestCase 面零登记**：P3 版本级缺陷（见 §二），G7 以来已知。
5. **计划预估 10–15 人日**：实际两个工作会话完成（模式全部复制自已验证链路 + 自动化脚本驱动）；提前不缩减验收面。
