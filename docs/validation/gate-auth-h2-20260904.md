## 一、S8：data-api `/internal/**` 切 OIDC 强制

### 机制（控制面代码）

- 新增 `data-os.auth.internal-mode`（env `DATAOS_AUTH_INTERNAL_MODE`，空值跟随全局 mode）：
  全局 DISABLED（dev 迭代态）时 `/internal/**` 面可独立 ENFORCED——服务间通道与门户用户登录解耦；
  全局 ENFORCED（生产默认）由主安全链的 `/internal/data-api/**` authenticated 规则承担，不重复挂链。
- 新增 `data-os.auth.jwk-set-uri`：JWKS 直连内网 Keycloak（`http://keycloak:8080/.../certs`），
  issuer 声明仍按网关 URL 校验——Java 侧免自签证书 discovery 依赖（S7 同型方案）。
- 失败语义：无效 token（BadJwtException）归一 401 ProblemDetail，非 500。

### Keycloak 侧（S7 模式）

- client `dataos-data-api`（service account，client_credentials）；audience mapper 注入 `aud=data-os`
  （实测 token：iss=网关 URL、aud=[data-os, account]）；secret 0600 文件 + dev `.env`（键
  `DATAOS_DATA_API_CLIENT_SECRET`；顺手清理了该 .env 中 3 个重复的 CONTROL_PLANE_IMAGE 键）。

### dev 实证（镜像 0.1.0-auth-h2-20260904，全局 DISABLED + internal ENFORCED）

| 用例 | 结果 |
| --- | --- |
| 无 token → `/internal/data-api/registry` | ✅ 401 |
| dataos-om-ingest token（aud=account，无 data-os） | ✅ 401（audience 拒绝） |
| dataos-data-api token（aud=data-os） | ✅ 200，registry 全量返回 |
| 门户面 `/api/v1/system/status` 无 token | ✅ 200（全局 DISABLED 语义保持） |
| **全链**：X-API-Key → data-api 查询 | ✅ 200 真实数据（22 行，46ms），审计回写经 OIDC `/internal/data-api/calls` 落库（h2-verify / 22 rows / 200） |

注：验证脚本初次 3R/4R 用例曾因探针引号错误全部误读 401（`-H "Bearer $T"` 在宿主机展开为空）——
容器内令牌传递须 `--entrypoint sh` 展开，已记运维口径。

## 二、S7 余项：JWKS 自签容错收口（内网直连替代 truststore）

- 三服务统一 `jwks-uri` 直连配置：control-plane（`DATAOS_OIDC_JWK_SET_URI`）、ai-ready
  （`AI_READY_OIDC_JWKS_URI`，dev compose 默认接内网 Keycloak）、quality-runner
  （`QUALITY_RUNNER_OIDC_JWKS_URI`，dev 暂空保持 DISABLED）。
- issuer 声明校验不动（仍按网关 URL）；ai-ready 的 `verify=False` 仅存留于 issuer-discovery
  兜底路径（注释载明），dev 主路径不再经过自签 TLS。
- 方案取舍：内网 JWKS 直连 vs 规划原词「truststore」——直连与既有 token endpoint 内网 http
  姿势同构、免证书轮换耦合、dev/生产同构；truststore 留作生产拓扑要求 TLS JWKS 时的替代（已记备忘 S7 行）。
- 范围边界：mpi-service 同型 OIDC 代码未接（dev DISABLED、issuer 空、无现实通道），接线配方一行即成，记 H4 复查。

## 三、S4 余项：guest-token 按用户维度重设计

- `SupersetGuestTokenService.issue(dashboardId, username)`：（用户 × 仪表盘）TTL 缓存
  （TTL−30s 安全边际；上限 1000 条，超限先清过期再整体让位）；同用户刷新页面不再重复压 Superset。
- 令牌用户名 `portal-` 前缀（非法字符收敛为 `_`，空身份回落 `portal-guest`）——与 Superset 真实账号
  （如 admin）隔离，Superset 审计可区分门户用户。
- 控制器从 JWT（preferred_username → sub）取身份；DISABLED/匿名回落共享访客（dev 实证签发两连发，缓存命中）。
- nginx 限流（10r/m burst5）维持不动。

## 四、随批修复（发现的存量缺陷）

- **`callsToday` 当日窗口时区缺陷**（DataApiAdminService）：原实现把本地日期墙钟当 UTC 午夜，
  00:00–08:00 CST 期间 overview 少计当日调用且与 `usedToday`（本地午夜口径）矛盾——凌晨跑测试暴露；
  已对齐为本地时区午夜。控制面全套 199/199 绿（新增 InternalApiEnforcementTest×5、S4 缓存/用户名×2）。
- **Python 套件**：quality-runner 33/33、ai-ready 42/42（各新增 JWKS 直连 2 例：只打直连端点、TTL 缓存）。
