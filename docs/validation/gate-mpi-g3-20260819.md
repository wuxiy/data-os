## 与方案的偏差（已在方案文档记录）

1. **B6' 召回收紧**：方案原文「姓名+性别」；EP 合成数据 1,433 身份仅 322 个姓名（单名最多 400 人），裸同名召回 7.6 万对噪声。实施修订为「同机构+姓名+性别+**联系方式哈希相同**」（数据内最强佐证，实测 3 对）。
2. **B3 零产出**：单源数据无跨源对（规则就绪，H2 测试覆盖）。
3. **KH 4413 形态**：该卡号 3 身份分属不同机构，B4（限同机构）不召回——保守侧正确；误合并拦截由同机构卡号复用对实证（见 #4）。

## 过程发现与修复（留档）

- 身份组标识必须含机构维度（`机构|系统|主键`）：两段键下 58 个跨机构同 PATIENT_ID 导致 JOIN 膨胀（133 判定 vs 44 对），修正后三态总和=候选数。
- 装载/候选/匹配结果统一「先清后写」全量重算纪律：UNIQUE KEY 覆盖无法收缩旧集合（旧 7.6 万对残留实证）。
- 幂等早退路径需补投影回写（装载重装重置 `mpi_person_id` 后 AUTO 幂等分支不再回写）。
- 容器多 JdbcTemplate 歧义：dorisJdbc 注册后必须 `@Primary` 主模板，否则 PG 语义注入解析到 Doris。
- PG 列名小写 vs 前端契约：详情查询需驼峰别名；链接列表过滤 `valid_to IS NULL`。
- Doris 方言：`GRANT ALL`（非 ALL PRIVILEGES）、UNIQUE KEY 必须为列有序前缀。
