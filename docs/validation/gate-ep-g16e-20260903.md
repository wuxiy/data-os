## 三、本批工程发现

1. **data-api registry 缓存 30s（REGISTRY_TTL_S）**：新登记的 Key/服务最长延迟 30s 可见——若在 TTL 窗口内实调会 401，等 TTL 或重启即愈（本批实测）。运维小坑入记忆。
2. **Superset chart API 不回 datasource_id**（G4 注释已知，重申）：datasource 从 chart params 的 `datasource` 字段取。
3. **Superset 凭据轮换后位置**：`DATAOS_SUPERSET_USERNAME/PASSWORD`（dev .env 81-82 行，安全批 S1 轮换口径）；G4 时代的 `/root/spike-hapi/superset-spike-pw` 已失效。
4. G4 seed 脚本的「重跑重复建图」缺陷在 G16e 脚本中修正（按 slice_name/table_name 查重跳过）。

## 四、与方案的偏差

1. 4 张图未用 headless 浏览器渲染验证（G4 验收机制同 dashboard 同引擎；以 dataset 列元数据 + 数值对账替代，嵌入渲染面零改动）；
2. 图表主题选择（链路/患者/订单/目录）为工程判断，未做业务 Owner 选题（G15B No-Go 中，语义线 parked）。
