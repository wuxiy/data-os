# 抽屉、弹窗与工作页的选择

本轮调整独立审核原型，正式门户尚未迁移。完整存量盘点见 [26 个覆盖层入口](OVERLAY-AUDIT.md)，参考源码证据见 [Continew 的实际分工](CONTINEW-OVERLAYS.md)。

2026-11-16 原型与容器原则已获用户批准；逐项实施按 [待审核的 FE0–FE7 计划](../../frontend-stack-migration-plan-20261116.md)执行，不据此自动启动代码迁移。

## 判断依据

先看用户的操作目的、是否需要原页面作为参照、任务长度、信息宽度和操作后果，再决定容器。字段数只作线索：三个字段加版本历史可能适合抽屉；两个参数加 SQL 结果比对也可能需要完整工作页。

| 容器 | 适用任务 | data-os 场景 | 不适合承载 | 退出与反馈 |
| --- | --- | --- | --- | --- |
| 右侧抽屉 Sheet | 从某个对象进入，快速核对其详情、历史或证据；需要保留列表的视觉上下文 | 运行速览、治理责任链、黄金人详情、单问题事件、前置机版本历史 | 复杂创建、SQL/JSON 长编辑、跨对象大表、仅一句话的确认 | Esc/关闭后返回触发对象；保留原列表筛选与位置；有未保存内容时先原位询问 |
| 中心弹窗 Dialog | 单步、边界清楚、短时间可完成的一次输入 | 数据源登记、任务复制、前置机登记、AI 产品登记、失败样本反馈、交付项目/对象登记 | 长配置、多轮试运行、持续看日志、跨对象审计 | 清晰的取消/保存；校验失败保留输入；脏数据退出保护；提交中防重复和误关闭 |
| 确认弹窗 AlertDialog | 用户需在明确对象与后果后作一次决定 | 规则删除、服务下线、AI 弃用/撤下、调度删除、MPI 拆分、批量通知 | 常规详情、连续表单、普通刷新/保存成功提示 | 显示名称/编号/影响/保留内容；初始焦点在取消；点击背景不提交；失败就地显示 |
| 独立工作页 / 业务 Tab | 长编辑、多步骤、宽表、SQL/JSON、历史和多次往返 | 新建/配置采集任务、数据源浏览、调度/实例/补数/日志、规则编辑、服务编辑、评分标准、问数审计 | 两三个字段的一次性补充操作 | 有明确返回路径；保存草稿；切换页面或关闭页签前保护未保存内容 |
| 常驻详情面 / 内联区域 | 持续比较、边选边看，结果要反复核对 | MPI 双身份复核、质量问题主从处理、映射/标准版本比较、交付验收、问数试运行 | 独立的全局任务、不可逆确认 | 不遮挡主操作；保留选择与输入；就地错误和重试 |
| 轻量浮层 Popover / 行内提示 | 低成本、短暂、无需阻断整个工作区 | 日期范围、用户菜单、通知预览、列设置；普通动作结果用行内提示/Toast | 危险操作确认、长表单和长内容 | 不锁住整个页面；Esc/点击外部可收起；关键信息仍能在原对象中找到 |

抽屉描述的是空间位置，模态描述的是交互行为。本原型的 Sheet 和 Dialog 都是模态层：背景列表可见，但不能同时点击。需要真正“边选择主表、边比较详情”时，选择常驻详情面，不能仅把弹窗挪到右边。该区别与 [shadcn Sheet](https://ui.shadcn.com/docs/components/sheet)、[Dialog](https://ui.shadcn.com/docs/components/dialog) 的组件语义一致。

## 本轮已落地的代表场景

| 操作路径 | v0.1 | v0.2 |
| --- | --- | --- |
| 数据接入 → 登记数据源 | 说明弹窗，没有登记表单 | 540px 中心 Dialog，来源名称/系统类型/接入协议，提交后为待检查 |
| 数据接入 → 新建采集任务 | 610px 抽屉内完成配置 | 独立任务编辑页，来源/模式/调度/增量与默认展开 JSON 并排核对 |
| 数据接入 → 任务详情 → 复制任务 | 未展开 | 两字段 Dialog；先关闭详情抽屉，副本不带运行状态和历史 |
| 数据质量 → 规则目录 → 删除 | 规则目录放在中心说明弹窗 | 目录是完整页面；删除使用 460px AlertDialog，显示规则对象与历史保留说明 |
| 质量问题 / 资产 / 任务详情 | 右侧详情抽屉 | 保留；问题处理说明有未保存内容时，关闭操作原位询问，不再叠第二个业务表单 |
| 通知 / 用户资料 / 日期范围 | 中心说明弹窗 | 轻量 Popover；日期可直接调整趋势周期 |

新任务页是容器与退出路径的审核样例。正式门户的完整库表选择、SQL、证据列和动态参数能力未迁移到此样例，不以它代替后续业务功能验收。

## 一致的操作规则

- 一个业务表单只占用一个容器。只读抽屉转复制表单时关闭抽屉，再打开 Dialog；不连开两层抽屉。
- 短表单的未保存询问留在原 Dialog；抽屉的未保存说明留在原抽屉。完整编辑页离开时用确认弹窗，可继续编辑或明确放弃。
- 删除确认与普通表单区分视觉语义和动作名称。删除按钮写“删除规则”，避免“确定”；取消优先获得焦点。遵循 [WAI-ARIA 对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 与 [AlertDialog 模式](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/)。
- 保存/删除执行中禁用重复提交及退出；失败保留容器和原值，错误显示在当前操作区。脏数据保护是本项目新增规则，不把它描述为 Continew 已全量具备。
- “已登记”“已进入发件箱”“已提交复检”不等于读取了院内数据、通知已送达或规则已通过。
- 全局审计、完整日志、宽数据结果不塞进弹窗；原本适合常驻的比较面继续留在页面。

## 目标技术栈映射

右侧详情用 shadcn/ui `Sheet`，短表单用 `Dialog`，决策确认用 `AlertDialog`，轻量预览用 `Popover/DropdownMenu`。独立工作页由 TanStack Router 表达；未来将对象定位、列表筛选和返回位置纳入路由状态。表单校验与服务数据生命周期分别由表单模型和 Query 管理，不把服务状态塞进容器组件。

这是审核后的实现约束建议，不表示目标技术栈已经安装或正式页面已经批量转换。
